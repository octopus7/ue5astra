# AstraLevelTest 작업 지시서

사용자 지시를 작업 중 계속 갱신한다. 작성일: 2026-09-07 (Asia/Seoul).

## 프로젝트와 제작 방식

- 현재 저장소 하위 `AstraLevelTest` 폴더에 Unreal Engine **5.7** 프로젝트를 만든다. 설치 버전은 5.7.4.
- 예상되는 게임 렌더 화면을 **이미지 생성으로 먼저 제작**하고 그 아트 방향을 기준으로 구현한다.
- 전체 배치 이미지는 작은 물체의 구조가 잘 보이지 않으므로 **개별 사물 모델링용 세부 참고 이미지를 별도로 생성**한다.
- **생성한 참고 이미지를 모두 프로젝트 안에 저장**한다. 사용한 텍스처와 생성 프롬프트 기록도 보관한다.
- 숲에 필요한 모델은 **Blender 스크립트로 생성**한다.
- **블렌더에서 전체 배치를 작성하고, 모델별 위치·회전·크기를 JSON으로 추출해 언리얼에 적용**한다.
- 블렌더 지형 높이 데이터도 함께 추출하고, 언리얼 지형은 실제 **Landscape**로 구성한다.
- 텍스처가 필요한 곳에는 이미지 생성을 이용한다.
- 탑다운 게임이므로 근접 시점용 세부 묘사는 필요 없다. 큰 형태·실루엣·색감과 화면 가독성을 우선한다.
- 새 TRS 기즈모 플러그인은 필요하지 않다. 회전·배치는 수치와 추출된 변환 데이터로 적용할 수 있다.

## 공간과 환경

- 크기는 **약 100 × 100m**. 기술적 Landscape 크기는 100.8 × 100.8m (127×127 높이 샘플, 간격 80cm).
- 숲, 공터, 호수, 개울물, 나무다리, 무너진 나무다리, 부서진 목조 건물을 포함한다.
- 호수와 개울 주변에는 **연꽃과 수초**를 배치한다.
- 바위는 회전·기울기·크기를 다양하게 하고 지면에 자연스럽게 묻어 배치한다.
- 중앙 공터와 주요 장소를 걸어서 탐색할 수 있도록 동선과 충돌을 구성한다.
- 작은 물웅덩이에는 **애니메이션 배경풍 하늘이 비친다**.
- 추가 수정 지시: 호수·개울·물웅덩이의 명확한 수면 경계를 마스크로 부드럽게 처리한다.
- 물웅덩이에 하늘 이미지를 직접 매핑하던 방식은 폐기한다. 실제 스카이에 구름을 넣고 반사 재질이 하늘과 주변 환경을 반사하도록 한다.
- 호수와 웅덩이가 칙칙하고 탁해 보이지 않도록 맑고 산뜻한 색과 반사를 구현한다. 흐린 반복 무늬와 과도한 흰 반사광을 줄이고 실제 엔진 렌더로 확인한다.
- 핑크 집 레퍼런스의 호숫가 수면을 목표로 삼아 구현 가능성과 방법을 새 작업에서 추론 강도 ultra로 검토한다. 품질을 위해 시간이 오래 걸려도 괜찮다.
- 호수·개울에는 하늘/구름 반사를 넣지 않는다. 웅덩이의 착시·텍스처 트릭을 허용했던 중간 지시는, 별도 수면 작업에서 전달된 최신 요청에 따라 **실제 스카이·환경 반사와 프레넬에 따른 시점별 반사 강도**로 대체한다.
- 호수의 화면상 오른쪽(3시 방향) 호숫가에 분홍색 지붕의 귀여운 집을 계획한다. 현관문은 게임 화면을 바라보고 앞에는 우물을 둔다. 우선 별도의 모델링 레퍼런스 이미지를 병렬 제작한다.

## 캐릭터, 조작과 카메라

- **나무 이정표**, **천막**, **화톳불**, **캠핑 요리 도구**와 야영 생활을 보여주는 소품을 제작한다.
- 리드타임을 줄이기 위해 **모델링을 개별 병렬 에이전트 작업으로 분담**한다. 최종 배치와 언리얼 레벨 저장은 한 작업에서 순서대로 적용한다.
- 새로운 개별 레퍼런스와 텍스처 원본, Blender 스크립트·모델·배치 데이터를 보관하고 작업 단위마다 커밋한다.

## 독립 호숫가 메시 제작 — 2026-09-07

- 사용자의 추가 지시: 물 표현 작업과 독립적으로 미리 제작할 수 있는 메시 모델링을 먼저 처리한다.
- 메시 종류별 병렬 에이전트를 할당해 리드타임을 줄인다. 얕은 바닥, 낮은 흙 턱, 수중 돌을 각각 제작하고 통합한다.
- 분홍 집 레퍼런스의 왼쪽 호숫가를 기준으로 Blender 원본, 개별 FBX, 재실행 스크립트, 자산 명세 및 실제 Blender 검토 렌더를 보관한다.

## 승인된 호숫가 개선 1~7과 최신 통합 순서

1. 얇고 불규칙한 흰 접촉 포말.
2. 물가 쪽으로 천천히 오는 1~2개 잔물결 띠.
3. 얕은 민트색에서 깊은 청록색으로 이어지는 수심색.
4. 모래 바닥의 큰 삼각면 인상 완화.
5. 깊은 바닥의 외곽 경계 숨김.
6. 해안 폭·돌출·작은 만의 변화.
7. 물이 닿는 흙·돌의 짙은 젖은 띠.

- 범용·현장 메시 총 13개, 현장 해안 액터 16개, 기존 해안 바위 39개의 젖은 재질 오버라이드, 기존 물웅덩이 5개를 대상으로 구현·검증한다.
- 수중 돌은 부드러운 노멀을 유지하고 `M_SubmergedStone/Light/Dark`의 기준색도 하나로 통일한다. 슬롯·UV를 유지하면서 연속적인 월드 좌표 색 변화로 삼각면별 색 차이를 없앤다.
- 검증은 별도 `L_AstraShorelinePolishModuleReview`와 `L_AstraPuddleSkyModuleReview` 맵에서 수행하고 원본 맵·공유 물/바위 재질 자산은 보존한다.
- 별도 검토 결과를 커밋으로 전달한 뒤 원본 맵에도 해안 1~7번과 실제 반사 웅덩이를 적용·저장했다. 기존 캠프 배치·Foliage·Landscape가 유지되는지 전후 비교한다.
- 원본 생성 파이프라인과 지형·물·하늘 갱신을 모두 마친 뒤, 의도한 맵에서 `apply_shoreline_polish.apply_polish(save=True)` 다음 `puddle_sky_reflection.apply_puddles(save=True)`를 **마지막에 실행**한다. 이후 원본을 재생성하거나 재질·액터를 갱신했으면 같은 순서를 다시 적용한다.
- 이전 `puddle_cloud_trick.py`를 최종 적용 순서에 섞지 않는다. 실제 반사의 낮은 각도와 탑다운 결과는 각각 `UE_PuddleSkyLow.png`, `UE_PuddleSkyTop.png`로 확인한다.
- 실제 정적 UE 렌더에서 접촉 포말과 1~2개 잔물결 띠를 확인했다. 저장된 맵을 다시 열어 16개 액터의 `NoCollision`, 39개 젖은 바위, 포말 그래프 검사 21개, 바닥·돌 5개 메시의 노멀 보존을 확인했다.
- `render_shoreline_motion.ps1`과 `verify_shoreline_polish.py`로 실제 게임 시간 13초/18초를 목표로 한 두 렌더와 저장 상태를 검토한다. `-AstraReviewCaptureSeconds=N`과 실제 월드 시간 로그를 사용한다. 최종 통과 여부는 `ArtSource/Previews/UE_ShorelinePolishValidation.json`, `ArtSource/Previews/UE_PuddleSkyValidation.json`에 기록한다.

- 호수에 걸어 들어갈 수 있는 목조 낚시 데크를 배치하고 낚싯대·낚시 의자·물고기 양동이·태클 상자를 함께 만든다.

- 기존 숲·수초·Foliage 군락과 동선을 살린다. 생활 영역에 겹치는 식물은 필요한 만큼만 조정하며 전체 밀도를 무조건 높이지 않는다.
- 실제 데크 보행과 진입로·가장자리 충돌을 확인한다. README 실제 화면을 갱신하고 완료한 작업 단위마다 커밋한다.
- 완료: 새 메시 15종과 개별 레퍼런스 4장·목재 텍스처 1장을 저장하고 메인 맵에 배치했다. W키로 데크를 8.9m 걸어 끝에서 정지하는 실제 보행 검사를 통과했다. 기존 Landscape와 재질을 유지하고, 새 소품과 겹치는 작은 식물 13개만 제외했다.

- 실제 UE에서 P 입력, 컷별 보행·접지, 반복 재생, 중도 취소와 복귀 후 WASD를 검증한다.

## 바위 형태 개선 — 2026-09-07

- 사용자 지시: 바위가 지나치게 둥글게 마모되어 조약돌처럼 보이므로 모델링을 개선한다.
- 넓게 깨진 면·불균일한 절리·층진 틈·비대칭 돌출부를 만들고, 기존의 부드러운 셰이딩과 애니 배경풍 생성 텍스처는 유지한다.
- 5종 세부 형태 레퍼런스를 별도로 생성·저장하고 Blender 모델링을 병렬 에이전트에 맡긴다. 원본·FBX·배치 메타데이터·검증 이미지와 생성 프롬프트를 보관한다.
- 기존 155개 바위의 위치·회전·크기·자산 참조 및 젖은 재질 오버라이드를 보존한다. README에는 실제 UE 렌더를 반영하고 작업 단위를 커밋한다.
- 완료: 5종을 새 형태로 교체하고 전체 Blender 배치와 UE 자산에 반영했다. 155개 참조와 전체 2,108개 액터 상태, 맵·재질·텍스처·Foliage 파일 보존을 확인했다. 실제 WASD·다리·캠프·낚시 데크 보행을 통과했으며 새 레퍼런스·프롬프트와 실제 렌더를 저장했다.

## Windows x64 패키지와 DLSS — 2026-09-07

- 독립 실행할 수 있는 Windows x64 패키지를 만든다.
- DLSS 지원을 포함한다. 요청의 해상도 기준을 4K 출력·1920×1080 내부 렌더링으로 우선 해석하고, 1080p 네이티브 실행 옵션도 제공한다.
- 설치된 UE 5.7용 NVIDIA DLSS 플러그인을 사용한다. DLSS Super Resolution Performance는 3840×2160 출력·1920×1080 내부 렌더링으로 설정한다.
- 1080p 네이티브와 4K 네이티브 실행 옵션을 함께 제공하고, 지원하지 않는 GPU에서는 1080p 네이티브로 실행한다.
- 패키지 실행 파일에서 실제 업스케일러·내부/출력 해상도와 P 데모 모드·복귀·WASD를 검증한다.
- 완료: Windows x64 Shipping 패키지를 생성했다. RTX 4060에서 세 그래픽 모드와 기본 실행 파일의 4K DLSS, P 데모 7개 컷·복귀·WASD를 검증했다. 실행 옵션 3개와 한국어 안내를 함께 배포하고 검증 자료를 보관한다.

## 두 번째 레벨: 우주선 착륙 숲 — 2026-09-07

- 기존과 같은 약 100×100m 규모의 별도 레벨을 만든다.
- 첨부한 형태의 은색 우주선이 기울어 착륙한 공터와 오솔길, 기존보다 큰 웅덩이를 구성한다.
- 갓 부러진 나무와 부러진 지 오래된 통나무를 서로 구별되게 만든다.
- 일반 버섯 군락은 15×15m, 발광 버섯 군락은 5×5m 범위다.
- 작은 옹달샘 주위에는 분홍색 나무를 배치한다. 수관은 애니멀 크로싱처럼 잎이 겹겹이 감싼 구형 뭉치다.
- 전체와 개별 모델 레퍼런스를 새로 만들고 원본·프롬프트를 모두 저장한다.
- 분할 가능한 모델링은 병렬 에이전트에 맡긴다. 물 반사 머터리얼과 스카이는 기존 자산을 재사용한다.
- 새 맵 이름은 `L_AstraStarfall`, 제작 기록은 `Docs/StarfallLevel.md`에 저장한다.

## 현재 확인된 도구 제약

- 컴퓨터 사용 플러그인의 언리얼 창 캡처가 `SetIsBorderRequired (0x80004002)`로 실패했다.
- 플러그인의 제공 API에는 데스크톱 전체 캡처 전환이 없다. 언리얼 창 접근성은 제목만 반환했다.
- 사용자와 협의한 제작 흐름에 따라 블렌더 배치 데이터와 언리얼 에디터 스크립트를 사용한다.
- 생성 참고 이미지를 실제 언리얼 결과물로 표시하지 않는다. 실제 렌더 검증 결과를 별도로 저장한다.

## 별도 레벨: 발광석 동굴 — 2026-09-07

- 약 50×30m의 어두운 동굴 내부. 두 차례 갈림길을 지나며 발광석의 빛이 공간과 이동 경로를 밝힌다.

- 독립 작업 사본과 자체 에디터를 사용한다. 원본 D:/github/ue5astra의 에디터·DLL·미완료 변경을 덮거나 종료하지 않는다.
