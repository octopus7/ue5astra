# BeastCrossing 후속 작업

기록일: 2026-09-07

추가 지시: 생성 이미지를 실제 텍스처 제작에도 충분히 활용할 수 있다. 기존의
‘이미지 생성은 레퍼런스 전용’ 지침은 이 지시로 대체한다.

**상태: 대기. 사용자 재개 지시 전에는 구현을 시작하지 않는다.**
이번 요청은 요구사항 기록만 포함한다. 자동 실행이나 예약 작업을 설정하지 않는다.

## 1. 언리얼 Ocean을 활용한 사실적인 바다 표현

- 상태: 대기 / 미착수
- 사용자 요구: 언리얼에서 제공하는 Ocean을 이용해 바다를 사실적으로 표현한다.
- 현재 상태: `L_Main`의 바다는 평면 메시와 절차적 색상 패턴을 사용한 초기 표현이다.
- 후속 방향: Unreal Engine의 기본 Ocean/Water 시스템으로 전환하고, 파도·해안 포말·수심에 따른 색 변화·반사와 굴절을 조정한다.
- 섬의 아기자기한 모델링 분위기와 조화되도록 수면의 사실성과 색감을 맞춘다.
- 해변과 선착장에서 수면이 지형을 뚫거나 연결부가 떠 보이지 않도록 수위와 해안 경계를 정리한다.
- 완료 기준: `L_Main`에서 기본 Ocean 기반 바다가 동작하고, 전체 섬 시점과 해안 근접 시점에서 수면 및 해안 연결을 확인한다.

## 2. 섬을 가로지르는 냇가 구현

- 상태: 대기 / 미착수
- 사용자 요구: 섬을 가로지르는 냇가가 필요하다.
- 현재 상태: 섬 내부에 냇가와 하천 지형이 없다.
- 후속 방향: 섬을 관통하는 연속된 유로를 만들고, 하천 바닥·둑·수면·물 흐름을 구성한다.
- 바다와 연결되는 부분의 수위와 지형을 자연스럽게 정리한다.
- 기존 집, 광장, 산책로, 계단과의 간섭을 검토하고 이동 동선을 유지한다. 횡단부가 필요한 경우 연결 방식을 함께 정한다.
- 정확한 유로, 폭, 깊이, 시작·종료 위치와 구현 방식은 작업 재개 시 결정한다.
- 완료 기준: 섬을 가로지르는 냇가가 실제 레벨에 존재하며, 물길이 끊기거나 둑·바닥·해안과 부자연스럽게 겹치지 않는다.

## 3. 생성 이미지를 활용한 텍스처 보강

- 상태: 대기 / 미착수
- 사용자 요구: 다음 작업에서 생성 이미지를 텍스처에도 충분히 활용한다.
- 생성 이미지를 레퍼런스에 한정하지 않고, 실제 Blender 및 UE 재질에 적용할 텍스처로 사용할 수 있다.
- 적용 후보: 모래·잔디·절벽·바위·목재·지붕·산책로·냇가 바닥 등. 필요한 표면에 적극 활용하되 섬 전체의 색감과 재질 표현을 통일한다.
- 재개 시 필요한 텍스처를 생성하고, 반복 타일링·해상도·UV·색상 공간과 재질 용도를 확인한 뒤 적용한다. 표면 요철과 거칠기 등이 필요하면 용도에 맞는 맵으로 가공하고 검증한다.
- 바다는 기본 Ocean/Water 시스템을 사용하는 기존 요구를 유지하며, 필요한 표면 디테일이나 마스크 등에 생성 이미지를 보조적으로 활용할 수 있다.
- 생성 원본, 프롬프트, 가공본과 적용 대상을 프로젝트에 기록한다.
- 완료 기준: 선택한 표면에 텍스처가 실제 적용되고, 근접 및 전체 섬 시점에서 반복 무늬·이음새·스케일·색감이 자연스럽게 보인다.

## 재개 시 확인할 사항

1. UE 5.7에서 사용할 기본 Ocean/Water 기능과 프로젝트 설정을 확인한다.
2. 바다 수위와 냇가 유로를 먼저 정한 뒤, 필요한 섬 지형 수정 범위를 정한다.
3. 현재 지형은 Blender에서 만든 정적 메시이므로, 물길과 둑을 만드는 데 필요한 지형 수정 방식을 검토한다.
4. `Scripts/import_island.py`의 재가져오기 과정이 새 바다·냇가 액터를 삭제하거나 초기화하지 않도록 함께 검토한다.
5. 지형 모델링이 필요하면 병렬 에이전트를 사용한다. 이미지 생성은 레퍼런스와 실제 텍스처 제작 모두에 활용한다.
